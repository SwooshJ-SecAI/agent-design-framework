# Contributing

This is a design-methodology repository, not a code project. Contributions that improve clarity, add worked examples, or refine the tier logic are welcome.

## How to contribute

1. **Open an issue first** for anything beyond a typo — describe the change and why it improves the framework.
2. **Keep the layering discipline.** New methodology content belongs in `docs/`; new fill-in skeletons belong in `templates/`. The README stays a lean entry point.
3. **No fabricated metrics.** This is an explicit design philosophy, not an empirical study. Keep claims honest — heuristics are fine, invented adoption numbers are not.
4. **New examples should show a decision.** A good worked example runs a raw idea through the tree and lands on a tier with clear reasoning, ideally contrasting with an existing example.

## Style

- Markdown, sentence-case headings.
- Tables for comparisons.
- Diagrams as SVG in `assets/`.
